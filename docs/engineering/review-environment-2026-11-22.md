## Local manual E2E proxy isolation (2026-11-22 Codex P2 follow-up)
A review finding showed that a manual `npm run e2e` could seed its disposable `E2E_API_URL` while a default Vite preview still sent browser `/api` calls to persistent :8080. The shared `web/src/e2eIsolation.ts` guard is now executed before setup requests and by Playwright's configuration. For local runs it requires explicit disposable opt-in, an origin-only loopback API URL, and no release/review ports. An external browser URL is permitted only for the repository's disposable Compose pair (:8083 browser, :8086 API). With no `E2E_BASE_URL`, Playwright starts its own :4173 preview, never reuses an existing listener, and the preview proxies `/api` to the same validated `E2E_API_URL`. CI jobs with both `CI=true` and `GITHUB_ACTIONS=true` continue to use their newly provisioned ephemeral backend and release-image port mappings. The guard lives under `web/src` because `web/.dockerignore` intentionally excludes `web/e2e` from the production image build.

Validation: 29 targeted isolation unit tests; negative CLI without flags fails before any setup request; an opted-in manual preview without `E2E_BASE_URL` passes authenticated desktop and mobile smoke against disposable :8086. The full isolated release-image E2E run passed with 57 tests and 17 expected skips; GitHub checks for the updated branch remain tracked in PR #430. No release :8081 data, clean review :8082 data, or production deployment was changed for this fix.

## Second Codex P2: reject local Vite development proxy (2026-11-22)
The first safety policy rejected reserved release/review ports but still accepted arbitrary loopback API ports. A local Vite dev server on :5173 can forward `/api` to persistent :8080; merely requiring `CERTFORGE_E2E_DISPOSABLE=1` cannot prove a port is disposable. The local E2E guard now uses a **strict API-port allowlist of :8086** with a bare loopback origin, rejecting :5173, :5174, :3000, :8099 and all other alternatives. An external browser URL remains restricted to :8083; without one, Playwright starts its own :4173 preview, proxying exclusively to the allowed :8086 backend. The hosted GitHub Actions fresh-database policy is unchanged.

Validation: **33 isolation regression tests**, explicit CLI refusal on :5173 before seeding, authenticated Playwright smoke on :8086 (desktop/mobile 2/2), TypeScript/ESLint, **353 Vitest tests**, build and unchanged gzip JS/CSS budgets, strict OpenSpec. A port allowlist is not proof of the process behind it: operators must start the repository's dedicated `certforge-e2e` Compose project; no custom API-port escape hatch was introduced. The release :8081 and review :8082 data were not reset or migrated.
