# CertForge — isolated review and E2E environments (2026-11-22)

## Reason
Screenshots of the old localhost:8081 installation showed `E2E fixture question` and synthetic `E2E reading 1` exam objectives. These are generated by `web/e2e/seed.ts` and `web/e2e/learner.spec.ts` and are not authored certification content. The original Docker project retains its PostgreSQL volume when restarted; `just up` does not remove fixtures.

## Safe environments
| Purpose | Web | Backend host | Docker project | Database volume |
| --- | --- | --- | --- | --- |
| Existing release data | localhost:8081 | 127.0.0.1:8080 | certforge-release | certforge-release_certforge-release-data |
| Clean review | 127.0.0.1:8082 | 127.0.0.1:8085 | certforge-review | certforge-review_certforge-release-data |
| Disposable E2E | 127.0.0.1:8083 | 127.0.0.1:8086 | certforge-e2e | certforge-e2e_certforge-release-data |

`just review` brings up the clean review stack and never imports questions. `just review-down` stops it while keeping its data. `just e2e-release` (also `just e2e`) runs tests against only the separate E2E stack, with both `E2E_BASE_URL` and `E2E_API_URL` pointing to its ports. E2E setup refuses unqualified local requests and rejects API ports used by the persistent release/review stack; GitHub Actions uses disposable CI services. `just screenshots` uses the disposable E2E stack too.

## What this does NOT do
- Does not remove or rewrite any of the existing 147 release questions or alter user progress.
- Does not automatically translate reviewed English question text: the interface locale is separate from the content's recorded source language and review digest.
- A certification topic with an explicitly reported published-question count of zero now shows a disabled practice action with an explanation; an unknown count still defers to server validation.
- Does not invent human reviewers or publish unreviewed certification content. The initially empty review stack is useful for catalog/UX review. To study real questions, use the existing editorial publication workflow with an actual reviewer identity and only valid recorded approvals. For example, set `WEB_URL=http://127.0.0.1:8082` for the existing `just reviewer` and `just publish-content` recipes.
- Does not claim physical device or real screen reader acceptance; issue #428 remains the human QA gate.

## Rollback
Stop the review stack with `just review-down` without `-v`; the release project and its volume are unchanged. No production deployment or migration is included in this change.
