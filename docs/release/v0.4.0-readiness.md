# CertForge v0.4.0 — Code Analysis readiness review

**Release candidate, not yet authorized for tagging or deployment.** Reviewed: 2026-11-19 (São Paulo). Merged baseline: `main` at `133f0bc1345b8908d03f934ad9cec388b3d0a8e4`.

## Verdict

**The engineering and editorial pilot is complete. The release itself remains gated.** The owner's explicit approval covered the six Java SE 21 pilot questions, their original keys and authored explanations (#417); it did **not** specifically confirm a manual screen-reader/keyboard-only review of the new terminal evidence panel in both languages. That accessibility gate, green CI for this release-candidate PR and a separate go/no-go to create a tag remain outstanding.

The last published GitHub Release was `v0.3.0` (2026-11-14). This candidate aligns `pom.xml`, `web/package.json` and `web/package-lock.json` to `0.4.0` without creating a release tag.

## Demonstrable learner outcome

A learner studies fixed Java 21 compilation, runtime and output questions with authored option explanations and deterministic Java evidence. Ordinary practice already displays fixed source and output after an answer; a **completed timed mock** now offers that same evidence in each expanded result review. An **active mock** continues hiding the key and its verification output, including through the ordinary practice route. There is no on-demand Java runner or new execution API.

The existing 150 Java SE 21 fixtures are not 150 newly authored or human-approved questions. Six representative examples were expressly approved by the owner, with original answers and Git blob hashes in [issue #417](https://github.com/vinicius-ssantos/certforge/issues/417). No content files were altered as a result of those approvals.

## Data and rollback

The comparison `v0.3.0...133f0bc` had 15 commits and **no changed database migration files**. Code evidence reuses `answer.verification` and the existing UI; it adds no database schema, API endpoint, user-code execution service or credentials. CI's ephemeral stack verifies image vulnerabilities, security headers, metrics/privacy, performance and backup restoration; these checks do not validate a production deployment.

Before deploying, review the actual target DB migration history, take and verify a backup, record image digests, and confirm rollback compatibility with the running environment and previous release. TLS termination and backup operations remain external to the images.

## Known limitations

- Prevalidated code evidence is not live execution or proof of semantic editorial quality by itself; the isolated Java runner belongs to `v0.5.0`.
- A 390px visual capture and browser/a11y checks exist in [PR #416's review](../review/pr-416/README.md); they do **not** constitute a manual assistive-technology walkthrough.
- No independent Portuguese translation/screen-reader audit has been completed. Exam scores are not predictions of official certification outcomes.
- The project's existing single-instance rate limiting, external TLS and backup/log handling limitations remain.
