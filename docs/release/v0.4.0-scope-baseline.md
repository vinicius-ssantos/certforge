# v0.4.0 — Code Analysis: verified baseline and scope decision

**Status:** proposal for review; no v0.4.0 release or feature implementation is authorized by this document.
**Baseline:** `main` at `eed366d` (18 November 2026), following frontend PR #412.

## Observed, already implemented

- The Java SE 21 content pack contains **150 question directories**, each with a fixed code sample (a `Main.java` or `modules/` graph) and `expected.txt`. These are checked by `ContentPackTest` using Java 21 compilation/runtime and matching expected evidence. Proof of a program's behavior does **not** mean human editorial acceptance of the explanation or all distractors (ADR 0011).
- `Prompt.tsx` already renders fenced code with a registered Prism grammar for Java, YAML, Dockerfile and HCL; supports plain-code fallback, wrapping, horizontal keyboard scrolling, line endings and CSP-compatible class-based styles. Covered by `web/src/ui/prompt.test.tsx` and the `question-presentation` OpenSpec.
- Learner practice and timed mock already have question explanations and delayed feedback semantics. The result screen supports filtering and topic follow-up.
- Thus issue #391's historical statements **“44 of 150”** and **“no syntax-highlighting dependency”** are outdated and must not be reused as implementation tasks.

## Gap audit completed

The read-only inventory and six case studies are recorded in `docs/release/v0.4.0-gap-audit.md`. It confirms 0 missing question/option explanations, 12 compile-error fixtures and a **concrete terminal mock review gap**: its API already carries verification source files and output, but the UI does not render them. The existing practice feedback does. This favors reusing the `VerificationEvidence` component and making its heading IDs unique; no new backend schema is justified. Owner acceptance of the minimal pilot remains pending.

## What is not established by that baseline

- That every code question's authored explanation clearly explains *why* Java 21 compiles, fails or produces the observed output, including misleading options.
- That learners can follow a step-by-step, accessible explanation in both practice feedback and finalized mock review, without revealing the answer prematurely.
- Whether a new UI or API is needed: existing `explanation` and per-option explanation fields may already be sufficient. No new schema, indicator or content publication should be assumed without a gap audit.
- Reliable code-specific learning/weakness metrics beyond existing topic progress were not demonstrated; this is **optional**, not a release blocker until the owner approves its measurable value.

## Proposed release outcome

A learner can inspect a fixed, reviewed Java 21 example, answer a compilation/runtime/output question, and—only when feedback is allowed—understand the actual language rule and result from an authored explanation. This is **not** an on-demand Java runner.

## Scope gates and evidence

1. **Gap audit:** sample output prediction, compilation failure, runtime behavior, modules and concurrency, across practice and terminal mock review; record exact missing learner outcomes.
2. **Owner scope decision:** reuse current feedback/presentation if acceptable, or approve a minimal enhancement to explain a bounded set of examples. No duplicate syntax-highlighter work.
3. **Editorial gate:** select a small, representative reviewed pilot. Do not count deterministic compiler tests as human approval; preserve question review/release governance.
4. **Behavioral tests:** verify no active-mock answer leakage, clear rule explanations after submission, readability and WCAG-relevant keyboard/mobile behavior, and CSP without inline styles.
5. **Release gate:** change implementation via separate reviewed PR(s), CI green and human acceptance before release tag.

## Deliberately excluded

Learner-supplied code execution (v0.5.0), sandbox/service provisioning, AI-generated answer keys, automatic editorial approval, all 150 questions being newly reviewed as a release prerequisite, invented certification pass probabilities and unverified evidence badges.
