# CertForge v0.1.0, Study Core: release notes (draft)

**Status: not released.** This is the draft that will become the release notes. The release is gated on the items in the [readiness review](v0.1.0-readiness.md) that only a person can do. Nothing here has been published as a tag.

## What it is

A study platform for the Oracle Java SE 21 Developer certification (1Z0-830). A learner practices by topic, gets feedback after every answer, and sees their history and progress. Editors write questions, a different person reviews them, and an administrator publishes them. The content policy allows only original questions, written and reviewed by people, and no copied exam material.

## What you can do

**As a learner**
- Create an account, sign in and out.
- Browse the certification track, its topics and the official objectives.
- Practice a topic: single and multiple choice questions, a confidence level for each answer, then whether it was right, a reason for every option, an explanation and official references.
- Finish or end a session; a session left idle expires and keeps the answers given.
- See every session and every answer again, and progress per topic.

**As an editor, reviewer or administrator**
- Write questions in a form that keeps unfinished drafts; send them for review with a list of anything missing.
- Review a question the way the learner will see it, approve it or send it back with a comment, and record which policy checks you did yourself.
- Publish and retire revisions (administrators), with a confirmation.
- Correct a published question by starting a new revision; see exactly what changed from the previous one.
- See who wrote, reviewed and published each revision, and the audit trail.

## What it guarantees

- **Answer privacy.** Until an answer is accepted, nothing the learner's browser receives, stores or shows reveals which option is correct or why.
- **History is evidence.** An answer always shows the question revision the learner saw. Replacing a question never changes it. The database refuses changes to attempts, published revisions and audit records.
- **Retry safety.** Submitting an answer twice, or retrying after a lost response, records it once.
- **Authorization.** Every endpoint has an explicit permission rule; a test generated from the application's own request mappings fails the build if one does not.
- **Safe errors.** Every failure has the same body, a stable code and a request id, and reveals nothing about the server.
- **Accessibility.** Automated WCAG checks on every page in a real browser, in both colour schemes, with reflow to a 320 pixel width; keyboard operation, focus management and screen-reader semantics. Manual review by a person is still to be done.

## How it is built and run

A Java 25 / Spring Boot modular monolith with PostgreSQL, and a React single-page app, packaged as two container images behind nginx (see [release environment](../engineering/release-environment.md)). The images are scanned for known vulnerabilities, the repository for secrets, and the code with CodeQL on every change. Backup and restore are rehearsed in CI.

Performance on a developer machine, one learner, one instance (not a capacity claim): every learner request at or under 20 ms at the 95th percentile except sign-in (about 60 ms, password hashing); the backend starts in about 7 seconds; the app downloads about 130 KB of compressed JavaScript and CSS.

## Known limitations

- **The content pack has not had its human review.** Twenty AI-assisted draft questions exist in the repository, with code that is checked to compile and print what the question says. Nothing publishes them automatically: a person must review them technically and publish them, so a fresh install has no questions until that happens.
- **No email verification and no password reset.** A forgotten password needs an administrator.
- **One backend instance.** Rate limiting is in memory.
- **TLS is not in the images.** Terminate it in front of the web container.
- **Staff see each other's email addresses** in staff-only screens.
- **Manual accessibility review is pending**, and is now a matter of judgement rather than coverage: whether the tab order reads naturally and whether status messages are announced as intended. Contrast in both colour schemes, reflow to 320 pixels, keyboard reachability with a visible focus ring, and the accessibility tree are all checked automatically.
- **No tracing yet**; metrics, health, logs and the audit trail exist.

## Deferred

Everything planned for `v0.2.0` and later: adaptive review, mock exams, code analysis, the secure Java runner, a study planner, an AI study assistant, and the interview-preparation track.

## Upgrading

This is the first release, so there is nothing to upgrade from. Migrations run when the backend starts, are forward-only, and follow an additive-only rule within a release (see the [operations guide](../engineering/operations.md#upgrading-and-rolling-back)).
