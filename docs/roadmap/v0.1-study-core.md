# `v0.1.0` — Study Core

## Release goal

Deliver the smallest trustworthy CertForge experience: a learner studies reviewed questions by topic, receives an explanation, and inspects persisted progress evidence.

## Primary learner journey

1. The learner signs in.
2. The learner opens the Java certification track.
3. The learner chooses a topic and starts a study session.
4. The system selects eligible published question revisions.
5. The learner submits selected options and confidence.
6. The system validates the submission and records an immutable attempt.
7. The learner sees the expected answer, explanation, and references.
8. The learner finishes the session and inspects topic-level progress and history.

## Editorial journey

1. An authorized editor creates a draft question.
2. Required metadata, options, answer, explanation, and references are provided.
3. A technical reviewer requests changes or approves the revision.
4. An authorized publisher publishes the approved immutable revision.
5. Later corrections produce a new revision; existing attempts remain unchanged.

## Capabilities

### Identity and access

- Individual learner account.
- Secure authentication and logout.
- Roles for learner, editor, reviewer, and administrator; roles may initially be combined operationally but permissions remain explicit.
- Authorization on administrative operations.

### Certification catalog

- Certification track and exam version.
- Ordered topics and optional subtopics.
- Active/inactive lifecycle.
- Java release compatibility metadata.

### Question bank

- Single-choice and multiple-choice questions.
- Immutable published revisions.
- Explicit lifecycle and review metadata.
- Authoritative references.
- Difficulty and question-type classification.

### Study

- Topic-focused session creation.
- Deterministic eligibility filtering.
- No answer disclosure before submission.
- Attempt recording with selected options, correctness, elapsed time, and confidence.
- Session completion and abandonment handling.

### Progress

- Attempt history.
- Basic topic summary: attempted, correct, incorrect, accuracy, and most recent activity.
- No opaque readiness prediction in this release.

### Operations

- Database migration health.
- Structured logs with correlation identifiers.
- Metrics for session creation, attempt submission, and failures.
- Stable error responses without sensitive details.
- Audit trail for question publication and deprecation.

## Acceptance criteria

- A learner can complete the primary journey without administrator intervention.
- Submitted attempts are idempotent or protected against accidental duplicate creation.
- A learner cannot retrieve correct answers for unanswered questions through ordinary learner APIs.
- Historical attempts keep their original question revision after later content changes.
- Unauthorized users cannot create, approve, publish, or deprecate content.
- Topic progress is reproducible from persisted attempts.
- Critical flows have automated unit, integration, and end-to-end coverage.
- PostgreSQL integration tests run through disposable test infrastructure.
- Primary learner interfaces pass baseline keyboard and automated accessibility checks.
- Logs and errors do not expose answers, credentials, tokens, or unnecessary personal data.

## Explicitly deferred

Adaptive scheduling, mock exams, arbitrary code execution, AI, mobile, payments, community publication, social features, leaderboards, and additional certification tracks.

## Demonstration script

The release demonstration must show:

1. an editor publishes a reviewed question revision;
2. a learner starts a topic session;
3. the learner answers incorrectly with high confidence;
4. the explanation and reference are displayed;
5. history and topic progress reflect the attempt;
6. a corrected question revision is published;
7. the previous attempt still displays the original revision.
