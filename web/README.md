# CertForge web

Learner web app (React 19, TypeScript, Vite). See [ADR 0009](../docs/adr/0009-web-frontend-stack.md).

## Run

```sh
npm ci
npm run dev        # http://localhost:5173, proxies /api to the backend on :8080
```

Start the backend first (see the root README). The app is same-origin with the API, so no CORS setup or token handling is needed.

## Checks

```sh
npm run lint       # ESLint, including jsx-a11y
npm run typecheck
npm test           # Vitest, Testing Library, vitest-axe
npm run api:check  # generated types match openapi.json
npm run build
```

## End-to-end tests

Playwright drives the real application (built web app, Spring Boot backend, PostgreSQL) on desktop and mobile viewports, and runs axe on every page it visits. CI does this in the `e2e` job.

To run them locally, start PostgreSQL and the backend from the repository root (the tests publish a few clearly labelled fixture questions through the editorial API, so the backend needs an administrator and relaxed reviewer separation, **for a throwaway database only**):

```sh
docker compose up -d postgres
./mvnw -DskipTests package
BOOTSTRAP_ADMIN_EMAIL=e2e-admin@example.com BOOTSTRAP_ADMIN_PASSWORD=e2e-admin-password-123 \
  java -jar target/certforge-*.jar \
  --certforge.question-bank.require-reviewer-separation=false \
  --certforge.identity.throttle.registrations-per-ip=1000
```

Then, from `web/`:

```sh
npx playwright install chromium   # once
npm run build
npm run e2e
```

The fixtures are test data. The Java SE 21 content pack awaits human review and is never published by automation.

## The API contract

`openapi.json` is generated by the backend, never edited by hand. After changing a controller or view:

```sh
./mvnw -Dtest=OpenApiContractIT -Dopenapi.update=true verify   # from the repo root
npm run api:generate                                        # from web/
```

Commit both files. CI fails when they are stale.
